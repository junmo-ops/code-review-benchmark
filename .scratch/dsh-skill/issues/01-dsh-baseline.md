# 01: 无待测 Skill 基线贯通现有测评

**What to build:** 测评人员在现有新建测评流程中选择 DSH + Skill 被测工具及无待测 Skill 基线，经现有队列完成一次 Linux 只读检视、独立选择的评分和普通批次报告。用最小案例验证完整路径，而不是先交付孤立的执行脚本或只有前端的选项。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 取得并核验固定版本的 Linux DSH 运行依赖、Node 要求和非交互调用，记录实际版本与依赖来源；Windows 包资料不能替代 Linux 运行证据，缺少依赖时报告实际阻塞，不静默换版本或用模拟执行器冒充已接通 DSH。
- [ ] 现有被测工具增加 DSH + Skill，首个可用模式为显式无待测 Skill 基线；新建、保存配置、排队、检视和查看报告形成完整用户路径，不新增独立实验入口，不自动生成其他批次或调用。
- [ ] 被测模型、接口、裁判和评分方法继续独立选择；同一类完整答卷分别验证原始 AACR 评分与 Martian 路由，原有协议的预算、轮次及重试不被替换。
- [ ] 复用已登记且资源可用的 AACR 清单，冻结实际案例与提交身份，不把内置单例或五例标识写成工具白名单；本票使用单例验通，规模和异常专项由 04 覆盖。
- [ ] 基线采用统一任务与答卷协议，每案例使用全新会话和隔离快照；不加载个人配置、其他 Skill 或仓库指令，不暴露参考答案、裁判材料或其他批次内容。
- [ ] Linux 只读隔离和工具限制实际生效：禁止写入案例、执行项目或 Skill 脚本、安装依赖、子代理及检视工具联网，受控模型接口通信除外；隔离不可用时拒绝运行，不退化为裸跑。
- [ ] 默认整例检视时限为 10 分钟，可按现有分钟设置调整；实际监督和终止进程树，单请求超时不冒充整例截止，清理时间单独记录。
- [ ] 显式关闭 DSH 模型请求、压缩失败和上下文溢出恢复的额外重试；通过本地受控接口的请求记录验证实际行为，而非只检查配置值，正常工具循环和固定策略压缩计入预算及用量。
- [ ] 完整空意见答卷有效；无效 JSON、非法意见位置、缺少完整结束及超时不能成为成功零意见。基线模式不因没有 Skill 加载事件而被错误判为失败。
- [ ] 普通批次记录、报告及下载可查看基线模式、DSH 身份、脱敏原始证据和已知用量；缺失用量不当成零，检视与裁判分别统计，缓存不重复累加。
- [ ] 经现有公开 API、队列和浏览器入口完成本地端到端验证，实际 Linux DSH 联调使用本地模型和裁判替身；不访问真实模型或 COS，并回归既有被测工具的创建及评分行为。
- [ ] 按项目约定完成 check、verify 和本票所需专项及 e2e；环境或校验阻塞如实记录，不能以源码内容断言替代验证或在未完成验收时标为 done。
