# 04: AACR 50 例连续运行与异常处理

**What to build:** 测评人员可用 Skill 模式或无待测 Skill 基线运行已导入的完整 AACR 50 例清单，看到准确进度和评分范围，并能安全停止任务、识别失败及恢复已有记录。一个失败案例不抹掉其余结果，中断和恢复不暗中产生新的检视调用。

**Blocked by:** 03: 指定 Skill 版本完成常规测评。

**Status:** ready-for-agent

- [ ] Skill 和基线分别创建普通批次，在正常成功专项中各自按已冻结的完整 50 例执行；核对唯一案例身份、实际提交、答卷数量及评分范围，不按显示名称猜数量，也不截断为单例或五例。
- [ ] 案例串行且使用独立会话和工作区，进度和批次外层预算按实际清单计算；默认 10 分钟是每案例检视时限，不是整个 50 例批次共用的时限。
- [ ] 连续执行后工作区和子进程有界并及时清理，队列心跳与页面状态更新持续工作；采样结果及观察时长如实报告，不将模拟规模验收等同于生产容量或真实模型性能。
- [ ] 单例检视失败保留其原始状态、耗时及证据并继续其余案例，失败不变为成功空意见；裁判失败、重试和恢复沿用用户所选评分协议。
- [ ] 报告显示全量完成率、失败、超时和实际评分或排除范围；缺失耗时或用量不伪装为零，检视及裁判统计分开，不输出自动跨批次优劣结论。
- [ ] 实际超时或用户停止会回收运行进程及后代，保留终止证据；通过本地受控程序及进程观测验证，不只断言曾发送停止信号。
- [ ] 隔离失效或冻结条件变化停止整个批次而非当成可忽略单例故障，不自动放宽权限、换版本或重试。
- [ ] 主动停止与服务中断状态明确区分；服务重启后中断批次不自动继续，也不重复创建 DSH 检视请求，失败检视重测另建批次。
- [ ] DSH 恢复只解析已有完整记录，无模型请求且不覆盖成功结果；原始记录完整但尚未转换时可恢复答卷，不完整记录仍保持失败，不能伪造零意见。
- [ ] 用本地执行器、模型接口和裁判替身验证完整 50 例、故障注入、队列取消及重启；保留请求次数、实际提交、评分范围、残留进程和工作区证据，不访问真实模型或真实 COS。
- [ ] 完成 check、verify、本地 e2e 和 e2e:explore，记录各项故障注入方式、持续时间与模拟边界；缺少浏览器或依赖时报告阻塞，不以场景数量或静态文件断言代替流程验收。
