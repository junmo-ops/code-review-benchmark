# 05: Skill 资产与测评证据跨容器恢复

**What to build:** 启用现有 COS 存储的工作台确认 Skill 导入成功后，容器重建仍能恢复并校验相同版本，并在原批次中查看答卷和实际加载证据。用户能分辨持久化失败和异步备份风险，而不是把当前容器里的文件误认为已经可靠保存。

**Blocked by:** 03: 指定 Skill 版本完成常规测评。03 已包含对 01 和 02 的依赖；本票不依赖 04，可与其独立推进。

**Status:** ready-for-agent

- [ ] 沿用现有资源与运行材料两条持久化链路及各自模式，不新增独立备份系统；本地模式仍可使用，COS 模式不退化为本地成功。
- [ ] COS 模式下原 ZIP、完整内容身份、文件清单及版本记录确认保存后才显示导入成功并可供新批次选择；保存失败时版本不可选，重新导入同一内容不会破坏既有版本。
- [ ] 上传确认检查实际远端对象大小和摘要元数据，下载恢复时计算实际内容摘要；不将元数据确认描述为已完整下载回读验证，也不承诺所有缓存文件均已事务回滚。
- [ ] 服务启动前恢复并校验 Skill 资产，原包和资源可追溯；缺失、损坏或不可变内容冲突明确阻断，不静默覆盖或用其他版本替代。
- [ ] 恢复后的版本仍可在现有新建测评中选用，历史批次仍绑定原不可变身份；不自动重跑历史检视来验证恢复结果。
- [ ] 批次沿用现有可备份的普通运行记录范围，脱敏事件、完整加载证明、配置身份、答卷及报告被明确纳入；临时 HOME 和工作区清理后不能失去唯一证据。
- [ ] 容器重建后可通过原有页面和报告下载查看已成功备份的批次材料，恢复及查看不产生模型调用，不改变所选评分协议的恢复规则。
- [ ] 运行材料沿用异步同步、失败警示与正常退出最终同步；同步失败对操作者可见，不承诺强杀、宿主故障或网络失败时最后瞬间数据零丢失。
- [ ] 使用本地 COS 替身、临时存储及容器或服务重启验证完整导入与恢复路径，覆盖对象保存失败、记录保存失败、内容冲突、恢复失败、临时会话清理和原始证据可读；不访问真实 COS 或真实模型。
- [ ] 完成 check、verify、相关存储契约测试、本地 e2e 和恢复 e2e:explore，记录注入方式、持续时间及模拟边界；本地模拟、Linux DSH 联调和行内镜像验收分别披露，不将未验证项标为 done。
