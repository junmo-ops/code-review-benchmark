# Python 3.12 行内容器试运行：部署后网页上传案例

本版范围：一个容器、网页工作台、一个后台 Worker、LCR 1.0.8。关闭浏览器不停止任务；容器停止会停止任务。案例在部署完成后由网页导入，原始 ZIP 同步保存到 COS；流水线不需要获取案例 ZIP。

## 1. 更新行内源码

下载最新的 `python312-container-patch.zip`，解压覆盖行内工程，提交源码更新。确保 `reviewers/lcr/` 的 Python 源码进入行内仓库；旧 `.gitignore` 会误忽略它，现已修正。

`aacr-pilot5-cases.zip` 是旧格式的 AACR 五例自包含包，仍可在网页导入。新流程先导入独立仓库资源 ZIP，再导入只含 dataset 的案例配置 ZIP；格式与命令见[案例集网页上传说明](案例集网页上传.md)。不提交案例 ZIP、`bundles/` 或 `repos/` 到 Git，Docker 构建也会排除它们。若之前已经提交过 bundle，可用 `git rm --cached -- bundles/cline__cline.bundle` 取消 Git 跟踪并保留本地文件。

## 2. 配置流水线

选择 Linux、Python 3.12 (Kylin) 构建引擎；代码根目录是含 Dockerfile 的项目目录。自动化编译脚本：

```sh
devops build --build.command="echo container_source_ready"
```

保留或添加平台的“发布容器制品库”步骤，使用根目录 Dockerfile。不设置 `BENCH_CASE_ARCHIVE_URL`，不在流水线上传或解压案例包；不运行之前的 `prepare_case_archive.py` 取包命令。发布容器制品库不用设置 `--build.dist`。

Dockerfile 使用两种已提供的行内镜像：

- 最终运行基础：`csbase.registry.cmbchina.cn/paas/cmb-python-3.12:c86-kylin10-v1`。
- 提取 Node 22/npm 并安装 LCR：`csbase.registry.cmbchina.cn/paas/cmb-nodejs-22.22:c86-kylin10-v1`。

镜像自动安装 Git、项目 Python 依赖和 Linux LCR 1.0.8，不复制 Windows/Mac 的虚拟环境，不需要旧 Python 3.11 wheelhouse 或 Linux 资源包。默认公司 npm 源为 `http://central.jaf.cmbchina.cn/artifactory/api/npm/group-npm/`，若平台实际地址不同，调整 Dockerfile 的 `NPM_REGISTRY` 构建参数及运行时 `NPM_CONFIG_REGISTRY`。

Python 依赖从公司 group-pypi 源按兼容范围解析，实际版本记录在镜像内 `/opt/deployments/requirements-container.resolved.txt`；试运行验收后再按实际版本固定依赖。构建检查 Python、LCR 和案例清单，不检查案例仓库文件是否已上传，不调用模型。

## 3. 配置容器运行参数

应用实例数量 **1**，服务端口 **8080**，健康检查路径 **GET /healthz**。使用 Dockerfile 默认启动命令，不覆盖为 `uv run python -m main`。默认一个容器同时启动 Web 和 Worker。

在平台设置环境变量和 Secret：

| 名称 | 填写内容 |
| --- | --- |
| `BENCH_PUBLIC_URL` | 浏览器实际访问的 HTTPS 根地址，不带页面路径 |
| `BENCH_BASIC_USER` | 自己设置的试运行账号 |
| `BENCH_BASIC_PASSWORD` | 登录密码，放平台密钥配置 |
| `BENCH_CASE_S3_ACCESS_KEY_ID` | 测评工作台专用 COS Secret；放平台密钥配置 |
| `BENCH_CASE_S3_SECRET_ACCESS_KEY` | 测评工作台专用 COS Secret；放平台密钥配置 |
| `BENCH_CASE_S3_SESSION_TOKEN` | 仅使用临时凭证时设置 |

平台入口提供 HTTPS，保留请求的 Host、Origin、Authorization 头。首次打开网页会弹出浏览器登录框。CSRF Token 自动生成，网页刷新后加载。服务启动不要求案例包已经存在。Dockerfile 默认启用 COS，未配置 COS Secret 或 COS 无法访问时，服务不会启动或确认导入成功。

案例包和运行记录复用当前测评工作台 COS 桶，运行记录单独放在 `code-review-benchmark/run-data/`。`deployment/case-storage.json` 沿用现有 endpoint、区域和桶名；桶策略还需允许运行数据前缀的列举、读取和写入，不需要删除权限。密钥只通过平台 Secret 注入。完整说明见[案例包 COS 存储](案例包COS存储.md)。

网页 ZIP 上传上限默认 **2 GiB**，解压总大小默认 **8 GiB**。可通过 `BENCH_CASE_UPLOAD_MAX_MIB` 和 `BENCH_CASE_UNPACK_MAX_MIB` 配置（单位 MiB，默认 2048 和 8192）。平台入口也需允许上传上限加 1 MiB 的请求大小余量，并设置至少 1800 秒的上传/准备时间；大型仓库或慢网络需继续增加。上传失败时先查看页面提示和平台日志。

## 4. 部署后在网页上传案例

1. 发布服务后，用平台分配的 HTTPS 地址打开工作台，输入上述账号密码。
2. 页面顶部显示“案例集导入”，选择行内电脑上的案例 ZIP。首次可以上传旧版 **aacr-pilot5-cases.zip**；其他案例集按[上传说明](案例集网页上传.md)打包。
3. 点击“上传并导入案例集”，等待案例校验、仓库提交验证和 COS 保存确认完成。不要选择加密的外层传输压缩包；如传输时加密，请先在行内电脑解密取得普通案例 ZIP。
4. 页面会列出已导入案例集。可以重复上传其他 ZIP；在新建测评或多模型实验的“案例范围”中选择要跑的案例集。重复上传同一份内容会提示已导入。
5. 在“模型配置”中添加 DeepSeek/Qwen 接口，建议先运行一个案例检查环境，再开始完整测评。并发在高级参数中设置。

上传和准备案例不调用模型。开始检视、评分和主动测试模型连接会调用模型。COS 写入异常时页面会提示未确认持久化；当前容器可能已经完成本地导入，检查网络和 Secret 后重新上传同一 ZIP 即可重试保存。已有测评批次会保留创建时复制的案例清单，不受后续导入影响。

案例包只包含仓库 Git 历史；案例清单、标准答案和评分逻辑仍在项目源码中。服务核对文件清单、SHA256 和五例所需的 base/head/共同祖先，案例文件存入 `/opt/deployments/runtime/repos`。

## 5. 重启、导出和运行数据

当前服务器没有持久化目录。独立仓库版本、案例清单和运行记录分别保存在同一 COS 桶的独立前缀；启动时恢复仓库目录、批次记录、任务日志、案例清单和 dataset。Git bundle 在相关测评任务启动时按需下载，准备期间任务会显示为运行中。运行数据每 30 秒扫描一次，持续追加的日志和原始输出也会生成快照上传，其余文件连续 15 秒未变化后同步；正常停止时会尝试最终同步。强制终止时，最后一次成功同步之后的变更可能丢失，实际窗口还受扫描和上传耗时影响。工作台同步状态异常时，不要重建容器。本地目录仍在时，恢复会保留本地已有文件。

若恢复的队列包含中断任务，Worker 保持运行并暂停领取任务，网页和历史结果仍可访问。操作员确认旧任务进程和容器已停止后，可在网页点击“确认旧任务已停止，恢复队列”；中断任务不会自动重跑，排队任务可以继续执行。

平台停止容器的宽限时间建议至少 30 秒。Web 或 Worker 任一退出时，容器入口会停止剩余进程。数据尚在的异常进程重启可能进入恢复阻塞，需管理员确认旧进程已停止后处理，不会自动重跑付费任务。

模型配置仍位于 `/opt/deployments/runtime/models`，含 API 密钥，不上传 COS；容器重建后应由平台 Secret 注入或在工作台重新配置。若平台之后提供持久磁盘，可把 `BENCH_DATA_ROOT` 和 `BENCH_CONFIG_ROOT` 指向挂载目录；SQLite 不直接放在 NFS/SMB 网络共享盘。

## 验证边界

之前的 Python 3.12 Web/Worker 与 ZIP 导入验证在 Mac 本机完成，使用的是本地存储模式，并非 COS 或行内镜像验收。本次按约定不新增、不运行测试用例；COS 读写权限、上传回读、容器重启后的 ZIP 下载与 Git 仓库恢复，需在行内首次部署后确认。镜像拉取、包源解析、入口上传限制和一例真实审查评分也仍需在行内确认。

此前在本机 Python 3.12 真实启动 Web/Worker，确认无案例也可启动、未上传时拒绝创建测评、通过 HTTP 上传约 24 MB ZIP 后还原仓库并成功初始化批次；模型调用 0 次。这些结果只覆盖本地存储模式。当前代码完成 Python 语法和配置格式检查；未新增或运行测试用例，未连接 COS，也未在行内构建镜像。
