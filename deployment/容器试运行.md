# Python 3.12 行内容器试运行：部署后网页上传案例

本版范围：一个容器、网页工作台、一个后台 Worker、LCR 1.0.8、AACR 五例。关闭浏览器不停止任务；容器停止会停止任务。案例在部署完成后由网页上传，流水线不需要获取案例 ZIP。

## 1. 更新行内源码

下载最新的 `python312-container-patch.zip`，解压覆盖行内工程，提交源码更新。确保 `reviewers/lcr/` 的 Python 源码进入行内仓库；旧 `.gitignore` 会误忽略它，现已修正。

`aacr-pilot5-cases.zip` 是独立案例包，约 24 MB，保存在你行内电脑上即可，稍后在网页选择上传。不提交案例 ZIP、`bundles/` 或 `repos/` 到 Git，Docker 构建也会排除它们。若之前已经提交过 bundle，可用 `git rm --cached -- bundles/cline__cline.bundle` 取消 Git 跟踪并保留本地文件。

## 2. 配置流水线

选择 Linux、Python 3.12 (Kylin) 构建引擎；代码根目录是含 Dockerfile 的项目目录。自动化编译脚本：

```sh
devops build --build.command="echo container_source_ready"
```

保留或添加平台的“发布容器制品库”步骤，使用根目录 Dockerfile。不设置 `BENCH_CASE_ARCHIVE_URL`，不在流水线上传或解压案例包；不运行之前的 `prepare_case_archive.py` 取包命令。发布容器制品库不用设置 `--build.dist`。

Dockerfile 使用两种已提供的行内镜像：

- 最终运行基础：`csbase.registry.cmbchina.cn/paas/cmb-python-3.12:c86-kylin10-v1`。
- 提取 Node 22/npm 并安装 LCR：`csbase.registry.cmbchina.cn/paas/cmb-nodejs-22.22:c86-kylin10-v1`。

镜像自动安装 Git、项目 Python 依赖和 Linux LCR 1.0.8，不复制 Windows/Mac 的虚拟环境，不需要旧 Python 3.11 wheelhouse 或 Linux 资源包。默认公司 npm 源为 `http://central.jaf.cmbchina.cn/artifactory/api/npm/group-npm/`，若平台实际地址不同，调整 Dockerfile 的 `NPM_REGISTRY` 构建参数及运行时 `NPM_CONFIG_REGISTRY`。

Python 依赖从公司 group-pypi 源按兼容范围解析，实际版本记录在镜像内 `/opt/deployments/requirements-container.resolved.txt`；试运行验收后再按实际版本固定依赖。构建检查 Python、LCR 和案例清单，不检查案例仓库文件是否已上传，不调用模型。

## 3. 配置容器运行参数

应用实例数量 **1**，服务端口 **8080**，健康检查路径 **GET /healthz**。使用 Dockerfile 默认启动命令，不覆盖为 `uv run python -m main`。默认一个容器同时启动 Web 和 Worker。

在平台设置环境变量：

| 名称 | 填写内容 |
| --- | --- |
| `BENCH_PUBLIC_URL` | 浏览器实际访问的 HTTPS 根地址，不带页面路径 |
| `BENCH_BASIC_USER` | 自己设置的试运行账号 |
| `BENCH_BASIC_PASSWORD` | 登录密码，放平台密钥配置 |

平台入口提供 HTTPS，保留请求的 Host、Origin、Authorization 头。首次打开网页会弹出浏览器登录框。CSRF Token 自动生成，网页刷新后加载。服务启动不要求案例包已经存在。

网页上传上限 **32 MB**。如果平台入口有独立的请求大小或上传超时限制，也需要允许 32 MB 请求和至少 180 秒的上传/准备时间；上传失败时先查看页面提示和平台日志。

## 4. 部署后在网页上传案例

1. 发布服务后，用平台分配的 HTTPS 地址打开工作台，输入上述账号密码。
2. 页面顶部显示“AACR 案例准备”，点击选择文件，选择行内电脑上的 **aacr-pilot5-cases.zip**。
3. 点击“上传并准备案例”，等待校验和 Git 仓库还原完成。不要选择加密的外层传输压缩包；如传输时加密，请先在行内电脑解密取得普通案例 ZIP。
4. 成功后页面显示“案例已准备，可以新建测评”，新建测评入口开放。
5. 在“模型配置”中添加 DeepSeek/Qwen 接口，先运行一例 `pilot1.jsonl` 审查和评分，通过后再运行 `pilot5.jsonl`。五例并发在高级参数中设置。

上传和准备案例不调用模型。开始检视、评分和主动测试模型连接会调用模型。上传失败不标记为已准备；可以修改问题后重新上传。已经准备好的案例无需重复上传，已有仓库不会被上传覆盖。

案例包只包含仓库 Git 历史；案例清单、标准答案和评分逻辑仍在项目源码中。服务核对文件清单、SHA256 和五例所需的 base/head/共同祖先，案例文件存入 `/opt/deployments/runtime/repos`。

## 5. 重启、导出和后续持久化

当前服务器没有持久化目录，因此页面会提示“试运行 · 重建后数据丢失”。容器重建后需要重新上传案例、重新配置模型；测评进度和结果也会丢失。完成测评后在批次详情导出并下载结果，再进行重发或重建。

平台停止容器的宽限时间建议至少 30 秒。Web 或 Worker 任一退出时，容器入口会停止剩余进程。数据尚在的异常进程重启可能进入恢复阻塞，需管理员确认旧进程已停止后处理，不会自动重跑付费任务。

之后平台提供持久存储时，再单独确认挂载方式。默认数据、配置、案例和 LCR HOME 均位于 `/opt/deployments/runtime`；`BENCH_STORAGE_MODE=persistent` 只改变提示，不会创建持久化能力。SQLite 不直接放在 NFS/SMB 网络共享盘。
