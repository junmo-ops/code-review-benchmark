# Python 单服务部署

生产环境只部署一个 Web 服务单元。构建时由 Node 22 编译 React，运行时由 Python/Gunicorn 同时返回 React 页面和处理 `/api`。浏览器访问同一域名，不需要前端代理服务，也不需要配置跨域。

## 流水线与服务配置

- 工作负载：`webservice`，国产化架构按现有服务选择 C86。
- 代码仓库：测评工作台仓库及目标分支。
- 构建上下文：代码仓库根目录。
- Dockerfile 路径：`backend/Dockerfile`。
- 构建阶段：Dockerfile 内使用公司 Node 22 镜像执行前端依赖安装、lint 和 React 构建；最终运行镜像仍为 Python 3.12。
- 启动命令：留空，使用镜像默认的 `python -m deployment.container`。
- 监听端口：`8080`。
- 存活检查：HTTP，端口 `8080`，路径 `/healthz`；仅检查页面服务存活，不因队列暂停或 Worker 心跳延迟重启容器。
- 页面存活和入口就绪探针均使用 `/healthz`，保持历史查询和人工恢复入口可访问。
- 任务就绪监控：`/readyz`；Worker 未就绪或队列暂停时返回 503。该端点仅供任务监控，不配置成存活探针或入口流量筛选，否则队列暂停后无法访问恢复页面。
- 实例数：当前保持 1 个副本。SQLite 和执行锁为单实例设计，COS 备份不是跨实例任务锁。
- 域名路由：现有工作台域名直接指向此 Web 服务。

不再创建单独的 Node 前端服务。前端的 `BENCH_API_UPSTREAM`、`HOST`、`PORT` 代理环境变量也不需要配置。

## 环境变量和存储

`BENCH_PUBLIC_URL` 设置为用户访问的 HTTPS 根地址，例如 `https://code-review-benchmark.paas.cmbchina.cn`。模型、认证、案例 ZIP/COS、运行记录/COS 等环境变量沿用后端当前配置；密钥由平台 Secret 注入。浏览器只接收页面和 API 响应，不接收模型或 COS 凭证。

运行时静态页面位于镜像的 `frontend-dist/`，只读。测评运行目录、模型配置、案例归档和其他可写数据继续使用现有运行目录及 COS 配置。Worker 的部署形态与当前版本保持一致。

上传案例或仓库 ZIP 时，平台入口仍需允许对应上传大小和处理时长。

## 本地开发与生产模式

```bash
npm run setup
npm run dev
```

开发时 Vite 提供热更新页面，Python 本地 API 监听 `8765`；Vite 仅在开发环境代理 `/api`。

本地验证构建产物：

```bash
npm run build
npm start
```

此时由 Python 本地工作台在 `4173` 端口同时提供页面和 API，与行内单服务结构一致。

## 发布验收

部署后先确认 `/healthz` 返回正常，再打开首页并确认 `/api/session`、`/api/state` 正常。随后由使用者验证登录、案例集与仓库管理、模型配置和创建测评等页面交互。真实行内镜像构建、平台认证和网关上传限制仍需在流水线环境验收。

## 长任务和中断恢复

容器重启后不会自动重放模型调用。打开原中断批次，点击“继续未完成案例并评分”，确认旧扫描进程已停止后，一次完成重新入队和解除暂停。完整答卷会跳过；有可用会话检查点的案例复用已完成文件，没有检查点时重跑该案例。旧的“恢复队列”按钮改为“解除队列暂停”，仅放行排队任务。

运行记录同步每 30 秒执行；案例完成后请求尽快同步。新增 LCR 会话检查点备份位于同一个运行数据 COS 前缀中的 `state/lcr-sessions` 清单，恢复到 `runtime/home/.leancodereview/sessions`。检查点上传会去除凭证字段并排除正在写入的最后半行，保留续跑需要的历史内容，不通过原始文件页面公开。现有 COS 凭证和环境变量无需新增。

强制退出仍可能丢失尚未上传的最后一段进度；检查点保存成功前不能保证文件级复用。新版本无法补回旧容器已经丢失的会话。网页显示最近 COS 同步时间，同步失败会提示。平台应保留上一次容器日志、退出原因、重启次数和内存指标，用于区分 OOM、探针失败与程序退出。

发布后验收：未就绪时 `/healthz` 应返回 200、`/readyz` 返回 503；Worker 恢复并解除暂停后 `/readyz` 返回 200。服务仍由 Python 单容器部署，本轮没有拆 Web 和 Worker。
