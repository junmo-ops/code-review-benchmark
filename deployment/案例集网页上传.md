# 通过工作台导入案例集

工作台把仓库历史和案例集分开管理。仓库资源包先上传一次；之后案例配置 ZIP 只包含 `dataset.jsonl`，并引用仓库名。已导入的案例集会保留，并出现在新建测评的“案例范围”下拉框中。旧版同时包含 dataset 和 bundle 的案例 ZIP 仍可导入。

目前支持 AACR、SWE-PRBench 和 CodeFuse 案例格式。每个 ZIP 默认最大 2 GiB，解压总大小默认最大 8 GiB。完整仓库无需为原来的 32 MiB 限制裁剪历史；可按实际案例规模调整上限。

## 首次上传仓库资源

仓库包应包含完整 Git 历史。把一个或多个已解压的仓库目录放在同一个文件夹中，确认每个仓库都有 `.git` 目录和有效的 `origin`，然后直接将这个文件夹压成 ZIP 上传。Windows 自带的 `tar` 可以把隐藏的 `.git` 一并放进去：

```powershell
tar -a -c -f D:\code\repository-resources.zip -C D:\code\aacr-repositories .
```

在工作台“仓库管理”页导入生成的 ZIP。服务端会递归查找 `.git`、读取 `origin` 识别 `owner/repo`，并整理完整提交历史。浅克隆、缺少有效 `origin` 或不含 `.git` 的 ZIP 会被拒绝。多个仓库可以放在同一个 ZIP 中。

仓库资源在服务端以 Git bundle 形式保存并按哈希去重；同一版本重复导入会复用。仓库历史有更新时，再上传新版本；旧版本仍保留，已创建的测评批次继续引用原版本。仓库页可查看版本历史、导入更新和删除未被案例集引用的仓库。原先生成 bundle 资源 ZIP 的脚本仍可用于已有流程。

## 生成只引用仓库的案例配置 ZIP

准备好符合相应套件格式的 JSONL 后，生成不含 bundle 的轻量案例包：

```powershell
py tools/build_case_config_upload.py --suite aacr --name "AACR 40 例" --dataset data\aacr-40.jsonl --output aacr-40-cases.zip
```

工具会从案例记录中提取仓库名。导入时工作台检查仓库资源是否存在，并用仓库历史校验案例的 base/head 提交。缺少仓库或提交时会指出问题，尚未开始模型调用。

如需从项目附带的 AACR 正样本清单中，按本地已有仓库挑选 40 例，可先运行：

```powershell
py tools/select_aacr_local.py --repos-root D:\code\aacr-repositories --limit 40 --output aacr-selection-result
py tools/build_case_config_upload.py --suite aacr --name "AACR 40 例" --dataset aacr-selection-result\selected.dataset.jsonl --output aacr-40-cases.zip
```

然后在“案例集管理”页上传 `aacr-40-cases.zip`。案例集页可查看、改名和删除网页导入的案例集；修改案例内容时，生成并导入新的配置 ZIP。后续换成 30、50 或其他数量时，只需重新生成并上传案例配置 ZIP，不必再次上传已登记的仓库资源。

如需打包 50 例，选择完成后使用专用命令生成轻量案例包：

```powershell
py tools/select_aacr_local.py --repos-root D:\code\aacr-repositories --limit 50 --output aacr-selection-result
py tools/build_aacr_50_upload.py --check-result aacr-selection-result\check-result.json --output aacr-bench-50-cases.zip
```

## 旧版自包含 ZIP 格式

旧包仍可用。它包含 `dataset.jsonl` 和每个仓库对应的完整 Git bundle：

先准备案例集 JSONL，以及每个仓库的 Git bundle。bundle 文件名必须是仓库路径把 `/` 替换为 `__` 后加 `.bundle`，例如 `cline/cline` 对应 `cline__cline.bundle`。

例如，将本地完整 Cline 仓库打成 bundle：

```bash
mkdir -p bundles
git -C /path/to/cline bundle create bundles/cline__cline.bundle --all
```

用 Windows PowerShell 时，将 `/path/to/cline` 换成仓库目录，例如 `D:\code\cline`。

在项目根目录执行：

```bash
python3 tools/build_case_upload.py \
  --suite aacr \
  --name "AACR 官方 30 例" \
  --dataset data/pilot30.jsonl \
  --bundles-dir bundles \
  --output aacr-pilot30-cases.zip
```

Windows PowerShell 可将命令写成一行：

```powershell
py tools/build_case_upload.py --suite aacr --name "AACR 官方 30 例" --dataset data/pilot30.jsonl --bundles-dir bundles --output aacr-pilot30-cases.zip
```

如果案例涉及多个仓库，`bundles` 目录中需要有它们各自的 `.bundle` 文件。脚本会校验案例清单格式并生成包含 SHA256 清单的 ZIP，不调用模型。

## 后台导入进度

点击“确认导入”后，上传请求只接收 ZIP 并返回任务编号；仓库资源准备、Git 提交校验和存储保存由后台执行。本地和服务端使用同一流程，页面每两秒查询进度，显示当前仓库和已校验案例数量。导入不调用模型。

已在本地缓存且大小和 SHA256 校验通过的仓库 bundle 会直接复用；缺失时才从 COS 恢复。案例集全部校验并保存成功后才发布为可用。失败时页面展示具体原因，服务日志保留异常详情；修复后重新上传配置包即可复用已准备的仓库。

导入期间不能修改仓库、案例集或提交新的测评任务。刷新页面可以继续查看任务进度。如果服务中断且任务记录仍在本地，重启后会将运行中的导入标记为中断，需要重新上传配置包。尚未完成的上传任务不跨容器重建自动恢复。

## 上传与选择

在左侧“仓库管理”中导入仓库资源 ZIP，再到“案例集管理”导入纯案例配置 ZIP。创建单模型测评或多模型实验时，在“案例范围”中选择需要的案例集。首次执行前会准备对应仓库；后续任务复用已准备的资源。

已有批次把当时使用的案例清单复制到自己的运行目录，因此之后继续上传不会改变已有批次。

仓库上传现在可直接使用普通 ZIP；ZIP 中每个仓库目录必须保留 `.git` 目录，例如：

```text
repositories.zip
  project-a/.git/...
  project-a/src/...
  project-b/.git/...
  project-b/src/...
```

服务端会从 `.git` 读取 `origin` 和提交历史，再保存为内部仓库资源。之前生成的资源 ZIP 也继续支持，结构为 `manifest.json` 和 `bundles/<owner__repo>.bundle`。

案例配置包结构如下：

```text
manifest.json
dataset.jsonl
```

案例配置清单的 `repositories` 是由案例自动推导出的仓库 slug 列表；清单 `files` 只列出 `dataset.jsonl`。旧版自包含案例包结构如下：

```text
manifest.json
dataset.jsonl
bundles/<owner__repo>.bundle
```

`manifest.json` 的格式由 `tools/build_case_upload.py` 生成。`suite` 使用上述三种 ID 之一；`files` 必须列出 ZIP 中除 `manifest.json` 外的每个文件及其字节数和 SHA256。

## 上传大小配置

本地与行内读取同一组配置，页面显示实际上传上限。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `BENCH_CASE_UPLOAD_MAX_MIB` | `2048` | 案例 ZIP 大小上限（MiB） |
| `BENCH_CASE_UNPACK_MAX_MIB` | `8192` | ZIP 内文件解压总大小上限（MiB） |

例如，在 Mac 终端允许 4 GiB ZIP、16 GiB 解压总大小：

```bash
BENCH_CASE_UPLOAD_MAX_MIB=4096 BENCH_CASE_UNPACK_MAX_MIB=16384 .venv/bin/python ui.py
```

行内在平台环境变量中设置相同名称和数值，重启应用后生效。平台入口的请求大小需允许 ZIP 上限加 1 MiB 余量；上传和导入超时建议至少 1800 秒，较慢网络或仓库更大时继续增加。这些限制由平台管理，应用代码无法覆盖。

接收、生成 ZIP 和解压均分块读写，不将整个仓库包载入内存。运行目录需要容纳上传 ZIP、解压的 bundle 和导入时用于校验的 Git 仓库；接收及解压临时文件在成功或失败后清理。导入文件 SHA256、路径与提交历史校验仍保留。COS 模式会把 dataset 和 Git bundle 分别保存，按资源 SHA256 复用相同文件；服务重启时只恢复案例清单和 dataset，测评任务使用案例集时再准备对应仓库。
