# 显式支持 POD 内 DSH 运行

2026-10-23，使用者在真实 Kylin V10 x86_64 POD 中确认官方包源已有 Bubblewrap，但普通账号运行 Bubblewrap 0.3.3 创建 namespace 被拒绝，随后明确选择“不额外套沙盒、在现有 POD 内执行”的方案 2。为适配该平台，新增显式 `pod` 运行模式；这项确认修订原规格的“只允许操作系统级只读隔离”，不是隔离失败时自动降级。

`sandbox` 保留原有 Bubblewrap 边界；`pod` 不需要 Bubblewrap/RPM，使用案例独立工作目录与 HOME、受限工具和路径 guard、清空继承环境、固定模型 Unix socket 转发及进程树回收。后者不保证阻止进程读取同容器数据、写文件或访问网络，不能将提示词、工具配置或检查通过称为操作系统隔离。所有模式都不执行待测 Skill 脚本，不改变正文、加载证明或评分协议。

运行模式在排队、初始化、执行身份和证据中冻结，并在页面与报告披露；更改模式须新建批次，历史答卷不自动升级。Python/CLI 缺省仍为 `sandbox`；行内容器 Dockerfile 明确选择 `pod`，DSH enabled 缺省仍为 0，只有依赖齐备并显式启用后才安装。POD 模式只需一个经校验的 npm 缓存归档进入 Git，不能把归档存在当作镜像、运行平台或真实模型/COS 已验收。
