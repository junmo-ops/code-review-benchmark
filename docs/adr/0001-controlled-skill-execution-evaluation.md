# 采用受控的 Skill 执行效果对照

本次新增测评用于比较代码检视 Skill 的效果，而不是仅给 DSH 与 Skill 的组合评分。固定检视执行器、模型、案例与预算，显式加载完整待测 Skill，与无待测 Skill 基线对照；排除个人配置、其他 Skill 及案例仓库指令文件的自动注入。相比执行器默认上下文，这一选择牺牲了部分日常使用的真实性，以减少未受控指令对效果归因的干扰。

最终产品接入范围收敛为：在已有“新建测评”的“被测工具”中新增 DSH + Skill，不新增独立的 Skill 实验入口。每批选择一个 Skill 版本或无 Skill 基线，不自动生成多组调用；不同 Skill 分别建普通批次。评分方法保持独立选择，沿用现有协议的预算、轮次和重试，不因切换被测工具而绑定专用评分。相比先前讨论的独立实验流程，这一选择缩小改动和工作流变化，不包含自动跨批次对比报告。

首期仅测 Linux 上的静态只读检视，使用统一答卷协议，但不改写待测 Skill 的正文和策略；超出能力范围的 Skill 不静默降级后评分。待测包采用不可变版本并保留原 ZIP，增加导入步骤以换取可追溯性。批次报告沿用所选评分方法，披露实际评分范围，不将不同条件或小样本成绩外推为普遍优劣。

2026-10-23 的运行隔离要求经使用者明确确认后由 [ADR 0002](0002-explicit-pod-dsh-execution.md)修订：可显式选择无额外操作系统级沙盒的 POD 模式，必须披露较弱保证、冻结模式，不能自动降级。其余受控输入、完整版本和评分原则不变。

AACR 案例范围复用工作台已有的可选清单，包括已导入的官方正样本 50 例；单例及五例仅用于接入试跑，不是功能限制。此前将它们写成首期白名单的方案遗漏了动态注册清单，已据用户指出的现有 50 例入口修正。

Skill 资产沿用现有资源持久化与恢复原则，批次材料沿用已有运行备份；不另建备份系统，也不承诺异步运行备份在强杀时零丢失。显式关闭 DSH 模型请求、压缩失败和上下文溢出恢复的额外重试，避免将隐藏恢复成本混入一次检视；正常工具循环与固定的上下文压缩仍计入整例预算和用量，不改变裁判协议的重试。完整范围及验收边界见 [DSH + Skill 测评方案](../DSH-Skill测评方案.md)。
