# 行内源码发布检视专用 DSH

公司 Git 禁止归档及相关二进制入库，外部 DSH npm 包又无法同步；使用者已确认 LCR 可从 Git 源码构建 `dist` 并由平台发布内部 npm，随后明确选择检视专用 headless 发行包。采用固定 DSH 发行版的可读 JavaScript/配置源码及保留许可证的第三方源码，在构建阶段编译必要原生组件，形成独立的内部运行时制品；不通过改后缀、编码或无后缀缓存将二进制放入 Git。

此包不是完整 DSH 产品，不携带 DSH 自带网页、语音、Office 转换或本测评禁止的交互工具；本测评网页、原生检视循环、Skill 加载、模型转发、工具限制和评分协议不因此删除或改写。内部发行版本、原生源代码提交、输入及输出摘要必须单独记录，不能冒称与官方预编译包字节相同。一次动态跟踪不构成完整依赖清单；源码构建、发布包还原和真实 DSH 对照回归分别验收，行内 Kylin 构建与发布仍需实际验证。

2026-10-26：使用者确认 npm 流水线构建节点固定为 Node22.9.0，没有可切换环境；公司源的 Node22.22.0 和 22.22.x 运行包均返回 E404，不再继续试版本或镜像。将构建宿主与运行目标明确分开：Node22.9 仅组装源码、严格安装 4 个满足该宿主 engines 的平台输入、用固定 Node22.22 头文件编译原生组件并打包，不在旧宿主运行 DSH。没有删除依赖、添加 overrides 或使用 force/关闭 engine-strict。

内部包升为 review.2，构建记录明确标注目标检查待执行，而不是把交叉打包标为 DSH 已运行通过。发布物附带固定摘要的目标检查程序；测评镜像安装与启动预检在 Node22.22.x 中强制实际执行原生模块访问、文件锁、grep、FFI 和 Sharp 检查，失败不发布已还原目录。DSH 的运行版本约束和原生 Skill 行为回归不下调到 Node22.9。源/制品摘要和该检查程序的摘要继续进入批准配置及冻结身份。
