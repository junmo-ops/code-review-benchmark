# Skill COS 改为追加发布

2026-10-28 行内手工探测证明，当前接口对 `If-None-Match: *` 和 `x-cos-forbid-overwrite: true` 均允许第二次写入，并实际覆盖原对象。使用者明确同意更改存储协议，而非跳过检查后覆盖旧的 `record.json`。

新发布放入独立的 `skills/append-v2/` 子目录。每次尝试使用新的随机事务标识，原 ZIP、版本记录及最终提交标记的路径均包含各自完整 SHA256；应用不更新索引或重写旧事务。每个对象写入后必须完整回读并重算摘要，最后才追加提交标记并确认本地版本。丢失响应只回读同一对象，不重放 PUT；重试创建新事务。没有提交标记的中间对象不会成为可选版本，也不会自动删除。旧协议只读恢复已提交数据，不改写旧对象，不再运行条件写探测。

这不是服务端防覆盖、对象锁或线性化的首次写入选主。它依赖事务标识与 SHA256 抗碰撞，以及所有合法写入者遵循新协议；有权限的外部程序仍可能破坏对象，读取时发现不一致必须停止。并发发布同一冻结身份可以合并记录，原 ZIP 字节和历史批次身份不变；同一内容身份出现不同的主原包等冻结字段时停止恢复，不能凭时间或排序悄悄替换已确认身份。冷启动时两份不同重打包 ZIP 的并发首次发布可能因此产生需要人工处理的身份冲突，不能承诺选出唯一成功者。顺序重打包导入仍保留原版本及每份原 ZIP。

更换容器后以发布标记恢复，继续核对本地确认记录、队列及批次冻结身份。完整命名空间和所有备份检查点同时丢失时不能证明历史从未存在；本地或模拟服务测试也不能代替行内 COS 验收。本协议不扩展为案例资源和运行备份的通用改造。
