# 本地测评工作台

本地工作台使用 React 页面和 Python 服务，复用 `backend/src/local.py` / `backend/src/mcr.py` 与已有模型配置，评分逻辑不变。开发时 Vite 提供热更新，构建模式下由 Python 同端口提供页面与 API；无需外部 CDN。

## 打开

首次执行 `npm run setup`。开发时使用 `npm run dev`，打开 `http://127.0.0.1:5173`。使用编译后的页面执行 `npm run build`、`npm start`，打开 `http://127.0.0.1:4173`。Windows 和 Mac 的双击脚本也调用 `npm start`。

本地默认提供左侧“案例集管理”（`/cases`），在该页面导入 ZIP 和查看可用案例集，使用和行内服务器相同的 ZIP 校验、Git 历史准备与案例登记流程；重复上传其他案例集后，可在新建测评中选择。内置案例仍可直接使用。要临时关闭上传入口，可运行 `.venv/bin/python backend/src/ui.py --no-case-upload`；显式启用可加 `--case-upload`。

开发模式下本地 API 默认监听 127.0.0.1:8765，由 Vite 代理访问。构建模式下页面和 API 由 Python 在同一端口提供。行内容器同样使用单个 Web 服务提供页面与 API，详见 [Python 单服务部署](../deployment/单服务部署.md)。

## 页面操作

1. **新建测评**：选择 AACR 主测、SWE-PRBench/CodeFuse 辅测或 MCR 多轮专项；选择现有数据清单、模型配置、检视对象、裁判与参数。创建只冻结批次，不调用模型。
2. **打开批次**：点击批次名称。可点击“一键检视并评分”，或分别检查准备、预览、检视、评分、生成报告、生成归档。MCR 不提供普通单轮预览。
3. **查看进度**：各案例顺序执行，每完成一步落盘；遇到失败停止后续步骤。日志页显示命令输出，原始文件页保留详细诊断。
4. **停止与恢复**：停止按钮终止当前任务的进程树。完整答卷保留，再次运行会跳过；失败尝试默认不自动重跑。检查日志后，才勾选“允许重试未完成尝试”。单轮原始进程成功但答卷尚未转换时，可选定案例点击“恢复答卷”。
5. **查看与保存报告**：中文报告直接展示，原始文件按批次查看；点击“生成归档”完成后，在原始文件页下载结果归档。保存当前日志是页面最近 200 KB，完整执行日志一直保存在磁盘。

评分会调用模型，部分旧协议的报告生成也可能调用翻译模型；按钮会提示。已有完整评分的“一键流程”跳过评分，不重复消耗 API。要比较其他裁判或模型，创建独立批次或沿用项目的同答卷对比工具，页面不改写旧分数。

## 模型配置

“模型配置”只管理一个模型的显示名称、模型 ID、接口地址和 API Key，不绑定裁判角色。显示名称支持中文，例如“内网 Qwen”，直接显示在卡片及模型下拉列表；模型 ID 才是实际发给接口的名称。配置文件名自动生成。显示名称独立保存于同目录的 `.label` 文件，备份配置时一起保留，不注入环境变量或模型请求。旧配置没有名称文件时使用兼容名称，不改写旧文件。可新增 DeepSeek / Qwen，保存不会调用模型，密钥不回显，同名配置不覆盖。服务器文件写入 `BENCH_CONFIG_ROOT`；本机默认写入项目根目录。

新建测评分别选择“被测模型”和“裁判模型”。例如被测模型选 Qwen，裁判选 DeepSeek；同一个模型配置也可用于两个角色。c-CRAB 使用发布测试判定，不显示裁判选择，仍沿用固定 DeepSeek 修复流程。

创建时会生成仅该批次使用的模型组合快照，后续操作沿用，不在模型管理列表重复展示。更换角色请创建新批次。已有批次与旧配置文件不迁移、不改写，继续使用原有检视与裁判组合。旧文件中的独立裁判若没有对应模型条目，可在裁判下拉中选择“沿用旧裁判配置”。

### 测试连通性

新增模型弹窗和配置卡片均可测试。每次仅向当前模型发送 1 个小请求（非流式、max_tokens=32），可能产生少量用量，不自动重试，不保存配置，也不会连带调用旧配置中的裁判。结果显示在对应卡片；修改弹窗字段后旧结果失效。

测试仅验证鉴权与基础文本响应，不保证 LCR 工具调用、长上下文或完整测评通过。服务器只读用户不能新增或测试配置。未提供网页密钥编辑；轮换批次快照密钥需要由运行机器管理员操作。

## 日志与服务生命周期

- `ui-state/jobs/<任务ID>.json`：任务状态、步骤、退出码。
- `ui-state/jobs/<任务ID>.log`：持续落盘的完整控制台日志。
- `ui-state/profiles.json`：批次选择的配置文件名，不包含令牌。
- 原有 `runs/`、`runs/mcr/`、`local-command-logs/` 的原始证据继续保留。

关闭或刷新浏览器不停止任务。页面服务的终端需要保持运行；正常 Ctrl+C、SIGTERM/SIGHUP 会尝试停止当前子进程树。电脑关机或强制杀进程无法继续跑；再次打开页面把未结束任务标为“曾中断”，不自动重试，也不把它记为成功。此时先检查原始日志和残留进程。

本地同一时间执行一个工作台任务；该任务内部案例并发由高级参数配置。不要同时在终端启动另一个操作相同仓库的评测。页面进度是完成案例/轮次与执行步骤数，不是模型内部推理百分比。

内网 Cloud 目前仍使用已有同步命令工作流。本页面的本机验证不代表 Cloud 的端口转发、后台存活、文件持久化或 Linux 执行入口已经验收；不能靠打开页面绕过平台限制。

## 验证范围

已增加命令与路径白名单、配置脱敏、跨站请求拦截、持久化、失败停止后续步骤、停止派生进程和重启不自动续跑等测试。浏览器验收使用创建、检查和预览等不调用模型的动作；没有为验证 UI 重跑付费 benchmark。
