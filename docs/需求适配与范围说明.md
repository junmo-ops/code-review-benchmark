# 需求适配与范围说明

更新日期：2026-10-01。

依据：[原始需求方案](../../../Spike%20Code-Review-Bench标准化案例集测评方案(4).md)、项目讨论中已明确的取舍，以及当前工程与运行证据。

本文记录当前实施口径，用于向需求方说明合理调整、资源限制和剩余工作；不表示需求方已完成正式验收。原方案保留，不覆盖历史要求。后续进度按调整后的目标评估，不把已说明的替代项重复列为开发欠项。

## 1. 保持不变的目标

在相同案例、明确的运行预算和评分条件下，比较公司代码检视 Agent / CLI 及候选模型，形成可追溯的质量、速度、Token 用量和选型结论。

- 指定候选仍为内网 Qwen 64k、Qwen 256k 与生产 DeepSeek 基线；实际服务名、版本和部署参数需与模型提供方核实。通用 Qwen 连通性成功不能代替指定候选的验收。
- 案例集、被测工具、模型、裁判和运行参数必须留痕；输入参考答案不提供给被测工具。
- 同一案例集内开展横向对比，不将不同案例集、评分协议的分数合并成一个总分。
- 接入成功、基础连通性、小样本真实执行和正式对照实验分别记录，不混称“已完成”。

| 原方案表达 | 实际实施口径 | 调整原因 | 覆盖范围与限制 |
|---|---|---|---|

| 最终选择 2–3 套测评集 | AACR 主测，SWE-PRBench、CodeFuse-CR-Bench 辅测 | 已确定与检视目标相符的组合，优先获得可重复的模型对照结果 | 各套独立报告；不是原清单里出现的基准都必须接入 |
| 本机部署模型并评估本机 GPU/显存 | 调用已有内网模型接口，工作台可部署内网服务器 | 用户已确认模型接口可用；模型推理由服务端承担 | 不要求前端同学本机部署模型；仍需记录可获得的服务端版本、量化、推理框架及限流信息，未知项标记未提供 |

| 本机执行作为主要运行条件 | 保留 Mac 本地运行，并准备独立 Web / Worker 内网服务器部署 | 长任务不能依赖个人电脑持续开机 | 服务器只是承载测评程序；不将公司 Agent Cloud 执行机制本身列为本次被测能力。目标平台仍需实际验收 |

## 4. 需要明确口径，不能直接删除的指标

原方案中以下要求仍有价值。采集困难时应说明限制并约定替代指标，不能以“接口无法提供”为由悄悄删项。

| 指标/要求 | 建议处理 | 当前状态 |
|---|---|---|
| 首响应延迟 | 明确是首字节、首 Token 还是完整响应；非流式请求完成时间不能冒充 TTFT。无法采集 TTFT 时标记不可得，提供端到端耗时与可观测请求耗时 | 正式口径待固定 |
| 上下文利用率及 64k/256k 比较 | 用单次实际输入 Token 和服务端实际窗口计算，并记录峰值、截断与长提交分层；不能用多轮累计 Token 除以窗口 | 样本及采集待补 |
| GPU、量化及模型版本 | 向内网模型提供方取得元数据；无法取得时记录未知，限定速度结论为当前接口条件下表现 | 待补齐，不要求自行部署模型 |
| Token 与成本 | 分开记录检视、裁判、失败/重试用量；缓存 Token 与实际价格分别披露，无价格时不估算金额 | 基础数据已有，统一汇总待补 |
| 问题级与案例级质量 | 明确命中、去重、匹配关系和分母。未匹配参考不直接等同于已证实误报 | 正式计分口径待固定 |
| Martian 原始精确率 | 保留原始结果；其非一对一计数已出现 Precision > 1，不能直接冒充常规精确率。正式报告采用何种一对一/去重派生口径需明确版本，不覆盖旧分数 | 已知限制，处理方案待确认与实现 |
| 人工双人复核及仲裁 | 在正式样本和争议意见上安排复核，保留结论；不必先开发完整标注平台，可使用结构化文件或表格 | 人员、范围与执行记录待落实 |
| 案例数与排期 | 根据覆盖目标、单例耗时和预算确定正式数量及分批计划；100+ 不是原文已确定的验收门槛 | 待确定 |

## 5. 调整后仍未完成的主线工作

以下是真实剩余项，不属于“不合理要求已排除”。

1. **确认三个指定模型**：核对内网候选 ID、64k/256k 窗口与生产 DeepSeek 版本，完成真实检视单例验证。
2. **接入公司检视 Agent**：当前公共执行器仅注册 LCR；MCR 直接模型、历史 OCR 均不能代替公司 Agent 适配完成。
3. **准备正式案例集**：固定来源版本、许可、抽样规则、标签/难度与标准答案。当前 AACR 五例为接入样本，来源记录的历史缺口必须披露；正式扩容需完整记录来源。
4. **固定实验与评分口径**：同一清单执行三模型 × 两载体，记录可对齐条件与差异；先跑共同小样本，验证统计有效后扩量。指定模型或载体不可用时记录缺失组合，不能宣称六组完成。
5. **补齐聚合统计与报告**：完成率、失败及重试、端到端时间、均值/P50/P90/吞吐、Token、问题类别/严重级别、案例级与问题级质量、相对基线差异及代表性样例。
6. **人工校准与 Golden 沉淀**：复核争议、仲裁分歧，形成可追溯、可回归的案例版本。
7. **内网实际验收**：验证服务器环境、认证、模型调用、长任务停止/恢复和证据下载。本机部署演练不替代内网验证。

MCR 与 c-CRAB 的专项剩余工作单列，不能用“已接入更多案例集”替代上述六组对照和选型结论。
