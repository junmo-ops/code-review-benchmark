# 执行与证据的架构约束

## 职责

- `runner` 管理跨工具可复用的案例预算、执行尝试和证据留存。接口接收执行函数和重试判定，不导入具体 reviewer。
- `reviewers/*` 负责工具参数、调用、原始结果转换及工具特有的完成判定。工具内部请求/压缩恢复与平台整例重跑分别记录。
- `suites/*`、`scoring/*` 负责案例协议与评分。完整答卷是评分输入，进程退出码或远程 SUCCESS 不能替代答卷格式检查。
- `webui` 发起操作、展示状态，不另建一套工具重试或费用统计逻辑。

## 本次落地范围

`runner/case_attempts.py` 提供共享截止时间、逐次证据归档和执行记录；当前先接入 DSH。LCR 已有会话恢复/attempts 协议，服务端 Agent 持有远程任务 ID，两者保留现有实现，后续迁移时必须保留各自幂等和恢复语义，不能直接套用整例重跑。

DSH 新批次冻结 `case_execution_policy`，答卷格式错误最多执行两次，共享 `timeout_minutes` 总预算。模型请求错误、权限/完整性错误不触发整例重跑。工具内部压缩恢复仍属于同一尝试，其用量计入该尝试。准备工作消耗预算，进程清理独立完成；截止时间不是操作系统级的瞬时强杀保证。

每次记录存于 `execution-attempts/<case>/<序号>/attempt.json`，结束后复制对应原始文件到该目录的 `raw/`。下一次开始前才能清除上一轮工作副本；归档失败则停止，不能继续覆盖。根目录 `raw/` 保持最后一次证据，兼容现有查看和恢复入口。仅按每次归档或当前工作副本读取一次用量。

只有通过答卷校验、执行清理及证据归档后，正常执行流程才发布结果。答卷带 `execution_attempts`；耗时覆盖全部已结束尝试，Token 是所有尝试的已知值，请求覆盖率单独保留。强杀可能留下 running 记录；这种情况不能宣称已取得完整费用和耗时。恢复只读取现有证据，不额外调用模型。

历史批次没有尝试台账时，按旧 raw 文件读取并标记历史未记录；不编造历史次数或费用，也不改写冻结配置来绕过工具身份检查。历史批次执行仍受原有运行时身份校验约束；升级后不承诺原运行时可被替换。

## 权限与对比

权限能力和隔离保证是不同维度。POD 模式无额外操作系统隔离；文件工具的路径 guard 不能约束 bash，chmod 不是针对同用户或 root 的强隔离。报告必须披露实际模式、工具、重试和预算。基线与 Skill 的工具权限不同，其结果是不同执行条件下的效果，不能全部归因于 Skill 正文。

当前远程更新开放 Skill 写入/bash 和有限恢复，已超出 ADR 0001/0002 的“只读、不执行脚本、不额外重试”表述；源码发行方案移除也与 ADR 0003 存在差异。本次记录差异并改善证据与披露，不把历史 ADR 当成这些新行为已获独立架构验收的证明。后续变更这些策略时需要同步决策记录、冻结配置和报告，说明兼容影响。

## 修改与验收顺序

1. 找到真实入口、冻结配置、失败分类、原始证据、恢复入口和报告消费者；写清拟改变的行为。
2. 保持原始请求和提交 SHA；兼容转换只能改变格式，不能擅自补造成功、模型身份、坐标或用量。
3. 明确每次尝试的身份和总预算。恢复同一远程任务不是新建任务；会话恢复不是整例重跑。
4. 通过现有本地检查，并用替身或已有归档验证失败后成功、预算耗尽、终态失败及重复恢复；不调用真实付费模型/COS。用户不要求时不新增测试文件。
5. 检查完整 diff，列出实际验证范围、跳过项和历史兼容限制。静态通过不等于行内验收通过。
