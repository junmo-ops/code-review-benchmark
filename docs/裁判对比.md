# 裁判切换与同答卷对比

新批次默认 `--evaluator martian`；明确传入 `--evaluator original` 使用原始大模型裁判。AACR 原裁判保留三轮语义判断与位置筛选；SWE 的 `swe_prbench_llm` 原裁判保留纯大模型一对一协议。历史 `swe_prbench` 仍是旧词面回退协议，不能将它当作纯大模型对照。

裁判模型仍从 model.local.json 的 JUDGE 配置读取。两边使用相同数据、检视答卷、裁判模型与接口。评分方式不同的批次分别落盘，旧批次不修改。

## 已有 AACR 答卷改用 Martian

以下命令在工程根目录执行，只调用裁判，不重复 LCR 检视：

```bash
run="aacr-martian-$(date +%Y%m%d-%H%M%S)"
.venv/bin/python local.py --timeout-seconds 60 init --suite aacr --evaluator martian --run-id "$run" --dataset data/pilot1.jsonl --timeout-minutes 10
.venv/bin/python tools/reuse_answers.py --source-run runs/aacr-smoke-20260930-230330 --target-run "runs/$run"
.venv/bin/python local.py --timeout-seconds 1200 eval --run-id "$run"
.venv/bin/python tools/compare_judges.py --left runs/aacr-smoke-20260930-230330 --right "runs/$run" --output "runs/$run/judge-comparison.zh-CN.md"
.venv/bin/python local.py --timeout-seconds 60 export --run-id "$run"
```

使用你实际完整答卷的来源批次替换 source-run/left；保持来源数据文件与模型配置不变。复用工具校验数据、检视配置和完整状态，不复制旧评分。

## 新检视同时保留两种评分

先用默认 Martian 批次执行 check → preview → review → eval。另建使用相同 suite/dataset 的批次，init 增加 `--evaluator original`，用 reuse_answers.py 从首批次复制完整答卷，再 eval 和 compare_judges.py。两边都 export。

SWE 新对照使用 `--suite swe_prbench_llm --dataset data/swe-prbench-pilot1.jsonl`；已有原裁判来源为 `runs/swe-llm-20261001-02`。其余步骤相同。

## 输出与边界

Martian 指标：metrics/martian.json；每对意见原始证据：judge/；中文汇总：report.zh-CN.md。对比命令输出 Markdown 和同名 JSON，包含答卷与指标哈希。

Martian 逐对比较参考意见和检视意见，调用量大致为两者数量之积。当前冻结串行一轮、单请求上限 180 秒；批量评估须根据意见数分批并设置平台时限，示例单例时限不是 100 例上限。错误记录不会当成零分的成功评分；重新评分请新建批次并复用答卷。

对比的是整套裁判方案（提示词、位置筛选、计数及轮次），不能把变化只归因于模型。两套数据集分别汇报，不混成官方总分。具体复用和差异见 [裁判层说明](../evaluators/README.md)。
