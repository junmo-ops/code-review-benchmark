# 测评对比规则

确认日期：2026-10-01。目标是评估行内不同 Agent/CLI 工具与不同检视模型在固定代码版本上的实际能力。

| 定位 | 案例集 | 当前状态 |
|---|---|---|
| 主测 | AACR-Bench | 已接入，已完成单例真实流程验证；正式样本待扩充 |
| 辅测 | SWE-PRBench | 已接入，已完成单例真实流程验证 |
| 辅测 | CodeFuse-CR-Bench（公开项目 SWE-CARE） | 已接入，真实检视单例完成；空答卷计分，未触发该例裁判 API |

主结论以 AACR 为主，辅测补充覆盖与交叉验证，分别披露差异，不合并三套分数，不按结果挑选案例。CodeFuse 已完成单例流程验证，正式范围待确定；接入范围见[CodeFuse 辅测](CodeFuse接入.md)。

原需求与当前实施范围的差异、暂不纳入理由和剩余工作见 [需求适配与范围说明](需求适配与范围说明.md)。

## 对比时固定什么

| 实验目的 | 可以变化 | 应当固定 |
|---|---|---|
| 比较检视工具 | LCR、OCR 等被测工具 | 检视模型与接口、案例清单、提交版本、可访问代码、运行预算、裁判和本套评分规则 |
| 比较检视模型 | 被测模型 | 工具版本与规则、案例清单、提交版本、可访问代码、运行预算、裁判和本套评分规则 |
| 补充不同案例集的证据 | 案例集 | 尽量沿用工具和模型配置；每套保留自己的评分协议，单独报告 |

工具特有的提示词、搜索和检视策略属于被测工具能力，不强制改成相同实现。无法对齐的配置须记录，结果不能解释成单一因素的因果差异。运行预算同时记录每文件超时、案例总时限、并发和工具调用上限；不同工具同名参数不一定具有相同含义。

## 当前基线

- 被测工具：LCR；当前公共 runner 仅注册 LCR，OCR 尚未接入这套新执行器。上表的工具对比是后续实验约定，不表示已经完成 LCR/OCR 对照。
- 检视模型与裁判模型：均使用当前配置的 `deepseek-flash`，承担不同角色；模型名不能代替服务端版本，能获取具体版本时一并记录。
- 同一套案例集内，所有实验组使用相同裁判模型、接口、提示词、采样参数、评分轮次和匹配规则。
- 新批次默认统一使用 Martian Offline 裁判适配；CodeFuse 已沿用该方案，保持数据集结果独立。
- `--evaluator original` 保留原始裁判作为对照：AACR 为位置筛选 + LLM 语义判断，行号容差 1，裁判 3 轮。
- SWE 选择原始裁判时使用 `swe_prbench_llm` 内部协议，裁判 1 轮，仅按大模型明确确认的配对做一对一计数；不使用嵌入或词面补判。目标是内部工具/模型对照，不复现官方榜单。旧 `swe_prbench` 协议仅保留作历史兼容。
- 原始裁判保留各自的提示词、轮次与匹配算法；与 Martian 的对比是整套评分协议对比，复用同一份完整答卷。

以上是实验约定；当前代码会冻结单个批次的配置与评分源码，但没有自动检查多个批次是否满足全部对照条件。

## 裁判验证与失败处理

正式扩大案例量前，人工抽查命中、未命中及争议意见。裁判配置一致不代表判断准确；同一模型兼任检视和裁判时，也需检查潜在偏好。重复评分用于观察波动，不能代替人工校验。

仅完整答卷参与质量评分，同时报告全批次的完成率、失败/超时数量、耗时和用量。失败案例不能静默删除，也不能当成完整的零问题答卷。只比较成功案例时，必须披露双方覆盖范围，避免因为失败样本不同而误判效果。

评分协议、裁判版本或嵌入后端变更时另建评分批次并保存来源关联，不覆盖旧分数。仅评分方式改变时应复用原始完整答卷；使用 `tools/reuse_answers.py` 校验相同数据、检视工具哈希、模型与接口后复用完整答卷；不复制旧评分，也不绕过冻结检查。

## 当前完成范围

已完成 AACR 与 SWE 各一例的真实 API 流程验证，操作及结果见[双案例集试跑](双案例集试跑.md)。尚未完成多工具对照、正式样本扩容及裁判人工校准。根据当前目标，不再将安装嵌入模型列为前置条件。LCR 行为和旧评分规则不变；新评分协议单独建批次。


## Martian 裁判接入（2026-10-01）

新批次默认采用 Martian Offline 裁判；原始裁判作为对照保留。比较 Agent/模型效果时必须固定 evaluator 及冻结参数；比较裁判时复用完全一致的答卷。原始 AACR 三轮与 Martian 一轮属于协议差异，需一起披露。详见[裁判对比](裁判对比.md)。

## MCR 多轮专项

独立历史回放协议，复用 MCR 一对一匹配，单独报告缺陷分数、匹配覆盖和状态准确率。直接模型与 LCR 分开列出；LCR 原生未输出状态时标记 unsupported。Martian 可做缺陷匹配对照，不替代状态评估。见 [MCR操作](MCR操作.md)。
