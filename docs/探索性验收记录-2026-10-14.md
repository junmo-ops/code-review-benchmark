# 探索性验收记录：2026-10-14

本轮在本地 macOS/Chrome、隔离前后端和真实 Git/SQLite/上传流程上进行。LCR 与裁判使用模拟结果，模型测试接口的失败由浏览器注入，未调用真实模型或 COS。

## 确认的问题与修复

共复现 7 个具体问题，归为 5 类根因。不是把 7 个测试失败直接当作 7 个独立根因。

| 问题 | 复现方式 | 原有表现 | 修复后的要求 |
|---|---|---|---|
| 旧保存响应关闭新模型表单 | 保存模型，扣住响应，关闭并打开另一份新表单，再释放响应 | 新表单被关闭，未保存输入丢失 | 保存结果只影响原表单；新表单和输入保留 |
| 旧测试错误污染新表单 | 连通性测试未返回时关闭重开，再返回 503 | 新表单显示上一份配置的错误 | 清空或修改表单后，迟到错误失效 |
| 模型删除失败没有可见说明 | 删除接口返回 JSON 503 | 确认弹窗缺少错误说明，浏览器出现未处理异常 | 弹窗显示错误，解除加载，允许取消或重试；HTML 503 也有说明 |
| 损坏上传记录阻塞操作 | 将上传 session 的 localStorage 内容变成损坏 JSON | 选择合法 ZIP 后无法继续导入 | 丢弃损坏的浏览器记录，重新查询服务端状态 |
| 过期上传记录阻塞操作 | 浏览器保留不存在的上传 ID，服务端返回 400 | 旧 ID 一直阻止新上传 | 清除确定失效记录；网络或 5xx 故障时不擅自丢弃断点 |
| 导入已受理但响应丢失后无法恢复 | complete 请求先到达后端，再中断浏览器响应，重试同一文件 | 后端已导入，页面却报会话已结束，不能直接继续 | 识别服务端关联的导入任务，恢复进度，不重新传输或提交导入 |
| 异常结构状态响应导致白屏 | /api/state 返回 HTTP 200，但 JSON 缺少工作台字段 | React 未处理异常，整页白屏 | 校验核心字段，保留上一份状态，显示错误并自动重试 |

主要修改点：模型表单请求归属、useAction 错误代次、共用删除确认交互、上传会话恢复、工作台状态响应校验。

## 连续运行、资源交叉和 50 例调度

本轮继续检查主动停止后的后续操作、排队时修改原模型配置、测评运行期间删除依赖及更新仓库，以及两轮各 50 例的调度。

### 复现并处理的问题

1. **主动停止后缺少明确续跑入口。** 原先仅 Worker 中断任务可继续，用户主动停止的批次只能看到原因与日志。未评分的单轮 LCR 批次现在可明确继续未完成案例并评分；可排在其他正在运行的任务后面。仍检查 Worker 心跳、批次锁、资源及版本；完整答卷跳过，不自动续跑或重放收费任务。
2. **已有评分时仍可提交必然失败的评分任务。** 现有后端有意保护已有评分不可覆盖，但限制原先在 Worker 领取任务后才出现。现在概览显示评分覆盖与限制，评分按钮禁用；持久队列 API 在入队前拒绝重复评分，补跑确认框也说明已有评分不会更新。当前仍不支持为原批次追加新的评分版本；补跑新答卷后若要全量评分，需新建批次。这项处理没有实现评分合并或覆盖。
3. **有效模型地址无法保存。** 默认 URL 表单规则拒绝 `http://127.0.0.1:9/v1`，导致后端已接受的配置再次编辑时无法保存。改为 HTTP/HTTPS 根地址业务校验；验证 IP 短端口、容器服务名可以保存，非 HTTP 协议、密码、查询参数及 `/chat/completions` 被拒绝。

## Linux 容器验收与导入状态恢复

### 本轮新增处理

1. **跨资源导入覆盖了旧任务终态。** 浏览器未收到案例集导入的最终结果便离页，随后导入仓库，再返回案例集页时，清单仍显示“后端导入中”，阻止选择下一份 ZIP。后端原先只有 `case-imports/current.json`；现在保留每个任务的状态文件并支持按任务编号读取。清单按自己的任务编号补齐终态，上传会话也读取已保存结果，不能把另一个导入任务的状态当作本批次结果。
2. **Linux 停止流程减少外部命令依赖。** 精简验收镜像没有 `ps`，停止时原先抛 `FileNotFoundError`，未清理进程，续跑又被旧锁拒绝。Linux 现在读取 `/proc` 枚举子进程，再执行已有的分组停止逻辑；macOS、Windows 分支保持原逻辑。行内 Dockerfile 原本安装了 `procps-ng`，因此这项不是对旧生产宕机的根因确认。
