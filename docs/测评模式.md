# 测评目的与执行记录

普通单轮测评创建时选择 `quality`（检视质量，默认）或 `stability`（运行稳定性），随 `run-config.json` 冻结，后续操作不能切换。MCR 多轮、c-CRAB 修复测试暂未接入这套稳定性统计；它们保留现有质量测评流程。历史批次不自动升级或补造执行记录。

## 执行差异

| 行为 | 检视质量 | 运行稳定性 |
| --- | --- | --- |
| LCR 平台额外重试 | 按配置，默认 1 次 | 0 次 |
| LCR 自动选择已有会话续跑 | 保留 | 关闭；显式补跑重新执行并单独记录 |
| DSH 最终答卷序列化错误 | 最多两次执行，共享总预算 | 一次执行 |
| DSH 平台配置的压缩重试、溢出恢复 | 各 1 次 | 各 0 次；正常上下文压缩仍保留 |
| 服务端 Agent 创建请求 | 不自动重放 | 不自动重放 |
| 服务端原任务恢复查询 | 保留 | 保留，不能改写首次等待失败 |
| 已有原始证据恢复、日志保存、Worker 中断标记 | 保留 | 保留 |

Agent 内部机制与平台整例重试不同。LCR 内部请求重试由其版本控制；Cline 仍使用适配器既有 `--retries 1` 配置；服务端内部重试不可从调用侧确认。此模式不宣称等同线上，实际参数仍需与线上核对。LCR 每案例文件并发仍为 1，流式及请求超时等由冻结的 `lcr_options` 披露；DSH 流空闲上限仍为当前适配配置。关闭平台补救并不恢复全部工具原生默认设置。

DSH 保留从说明文字/代码块提取完整 JSON 的兼容解析，并在成功答卷和执行记录中保存 `raw_format_compliant`。该处理不增加模型请求、不修补截断 JSON。原始格式合规与适配后形成完整答卷是两项不同结论。

## 证据和统计

新批次每次执行写入 `evaluation-attempts/<case>/<唯一编号>.json`。先写 running，再记录终态；下一次执行使用新文件。异常强杀遗留的 running 是未知状态，不假定已成功或失败。首次执行记录不会被补跑替换。

批次详情实时显示首次完整答卷数、首次结果覆盖、后续执行/恢复查询次数、首次及累计已知耗时和 Token。生成中文报告时补充同一口径，并导出 `evaluation-summary.json`，含逐案例记录和失败原因。

- 首次完整答卷率：首次成功数 / 已结束且有记录的首次执行数。已识别的平台故障和主动中断剔除，单独保留。未确定归因的错误仍显示为未分类，不直接称为 Agent 故障率。
- 最终完整答卷数与首次结果独立。评分失败不改变被测工具的首次执行结果。
- 耗时为已记录尝试的累计执行时间，不是批次墙钟耗时；不含未被观测器覆盖的准备阶段和进程外等待。缺失值不按零统计。
- Token 仅累计已知、可相加的数据，并披露记录覆盖。DSH 读取逐请求用量，失败尝试有记录时也计入。LCR 会话续跑可能报告累计用量，未确认增量时不累加；恢复查询不重复累计远端任务用量。
- 平台故障识别限于明确的本地系统/隔离错误；网络、远端失败和格式错误等保留原始错误类型及信息，不能仅凭文字猜测责任归属。
- 历史批次缺少该协议时，首次成功率和用量为未知。历史执行仍须通过原有工具身份校验；更新适配器不代表旧冻结批次可以改用新运行时继续执行。

手动补跑沿用原有工具限制：LCR 可以显式补跑，服务端 Agent 恢复原任务查询；DSH/Cline 已有失败证据时仍要求另建批次，不擅自解除其防重复执行约束。

## 验证边界

本地以现有校验和替身执行验证模式冻结、质量模式失败后重试、稳定性模式首次失败即结束、首次记录不被补跑覆盖、原任务恢复不重复累计 Token、历史未知值及报告重复生成。未调用真实模型或 COS；未验证行内服务的内部重试策略或等同线上配置。
