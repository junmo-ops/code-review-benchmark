# 对比实验与一对一评分

本入口用于比较同一个 LCR 工具下的多个模型。支持 AACR、SWE-PRBench、CodeFuse；每次选择一套，不合并跨套分数。公司 Agent 适配及正式指定模型的内网结果仍是后续工作。

## 页面操作

1. 在“模型配置”中准备至少两个模型接口和一个裁判接口，先测试连通性。
2. 左侧“多模型实验” → “创建实验”。
3. 选择同一套案例，勾选 2–6 个被测模型，选择统一裁判。建议先用 AACR 1 例验证，再用现有 5 例做小规模对照；这不是正式代表性样本。
4. 设置每案例检视总时限。开始后逐模型、逐案例串行执行，会产生检视和裁判用量。
5. 在“多模型实验”打开实验查看执行进度、日志和各组原始记录。
6. 到独立的“结果对比”页面，选择已有实验查看报告并下载中文 Markdown / JSON。查看结果不会调用模型，不需要重新创建实验。

当前结果对比以同一实验内的模型组为范围，不支持任意混选历史批次，以免将不同案例、预算或评分协议混为一组。

检视总时限默认 10 分钟，每文件 LCR 超时也采用该值；外层可提前终止整个案例。每案例裁判总时限固定 10 分钟，单次请求 180 秒；最多 400 个参考×检视意见对，超过预算标为评分失败，不随机丢弃意见。模型列表顺序决定执行顺序及报告差值的首组基准，首组不自动等同于生产 DeepSeek。

实验创建时冻结案例清单哈希、各角色模型配置、工具及评分实现。排队期间有变化会停止，不能带着不同条件继续比较。每组使用独立新批次；旧报告与分数不改写。不自动重试失败案例。停止或服务中断保留已有结果；此版本不提供实验内重试/自动续跑，确认旧任务停止后另建实验，重跑会产生费用。

## 评分口径：martian_one_to_one_v1

- 复用固定的 Martian Offline 意见对提示词和裁判响应校验；不调用上游非一对一计数函数，不修改旧评分器。
- 对每条参考和每条检视意见做语义匹配，保留布尔判断、置信度与理由。`match=true` 为匹配边，不引入额外置信度阈值。
- 按原始列表索引构建二分图，计算确定性的最大基数一对一匹配。每条意见和参考最多使用一次；相同文本仍作为独立记录，不偷偷做语义去重。输出重复本身可能降低精确率，应结合明细解释。
- TP=匹配对数，FP=检视意见数−TP，FN=参考数−TP。FP 仅表示未匹配参考，不能据此认定事实误报。
- 问题级 P/R/F1 使用共同案例的总计数计算；案例宏平均对同一共同案例集逐例平均。这不是二分类“有问题/无问题”的案例准确率。
- 完整零意见答卷正常计分：P/R/F1=0，FN 为参考数，不触发裁判调用。空参考拒绝计分。
- 裁判错误、截断、超时或配对预算超限不发布该案例分数，保留已发请求。失败不当成零意见。

报告主表只比较所有组共同完成评分的案例，并披露共同案例数。JSON 同时保留各组自身成功案例指标。共同集太小或完成率差异明显时，不据此给出总体优劣结论。

## 统计与证据

- 每组完成数、评分完成数、失败数、外层超时数及逐案例状态。
- 检视命令耗时、均值、线性插值 P50/P90；包含已记录失败尝试，包含进程启动开销。
- 检视阶段有效完成数 / 检视累计用时的吞吐，不包含准备、裁判及排队时间；不能当作整个实验的墙钟吞吐。
- 输入/输出/总 Token 的已知总值与均值、用量覆盖数；裁判响应 Token 独立列出。失败请求无法取得用量时不补猜，已知用量不是完整计费。
- 共同案例的问题级指标、案例宏平均、相对首组差值及逐例明细；不生成没有证据的选型推荐。

控制目录为 `runs/compare-<实验编号>/`：`experiment.json` 冻结清单、`comparison.json` 汇总、`report.zh-CN.md` 报告、`logs/` 阶段日志。分组目录为同级 `compare-<编号>-gN/`，保存原检视答卷、`comparison-status/`、`comparison-judge/` 请求证据和 `comparison-scores/` 一对一分数。完整分组才生成 `metrics/one-to-one.json`。模型密钥仍留在配置目录，不写进实验清单和页面响应。

当前首响应延迟、上下文利用率、统一严重级别/问题类型分布、人工复核与生产六组正式对照尚未完成，不用当前汇总替代这些验收项。此版本没有修改 CLI 行为，没有执行真实付费对比，也没有运行浏览器自动化验收。

## 工作台结果阅读

- “单模型测评”用于一个被测模型；“多模型实验”固定条件顺序运行多个模型；“结果对比”只读取已有结果。
- 可填写中文显示名称，技术编号自动生成。显示名称存于工作台元数据，不修改冻结协议与历史报告。
- 创建前显示案例范围、模型数量及执行时限。单模型的每文件任务时限与多模型的整例时限分别说明，不改变既有执行预算。
- 实验结束后按完成情况显示“全部完成”“部分完成”或“无完整评分”，保留底层失败状态。分模型显示检视、评分及超时数。
- 结果页先显示共同案例范围、完成率与指标；完整报告仍可展开、下载。未完成答卷没有质量分。
- 点击案例可核对参考意见、模型意见、最终一对一匹配、裁判原文理由、未匹配条目与原始文件。诊断摘要区分整例超时与日志记录的请求时限到期；缺少结束记录不代表进程仍在运行。
- 一级菜单与详情、页签使用 History 地址。详情参数保留在 URL 查询字符串中，支持刷新、前进后退与复制地址；地址不包含模型密钥。
- 这些是只读展示与导航优化，没有新增评分、修改 CLI 或重跑模型。人工复核结论的编辑保存尚未加入，本页展示的是原始证据。
