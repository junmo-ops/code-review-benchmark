# 开发校验与交付

## 开发后检查

在项目根目录运行：

```sh
npm run check
```

依次校验 Python 语法与复杂度、全部前端源代码规范、Node 项目脚本规范、TypeScript 类型。前端与脚本的复杂度上限为 15；Hook 依赖警告和其他警告都会使检查失败，不允许提高阈值或关闭规则绕过。

## 提交前自动阻断

每台开发电脑执行一次：

```sh
npm run hooks:install
```

这会将当前仓库的 Git hooks 目录设为 `.githooks`，替换之前自定义的 hooks 路径。之后提交时自动运行 check。默认不自动修改开发电脑的 Git 配置。Git hook 是本地辅助，镜像构建检查才是流水线保障。

## 发布与交付检查

```sh
npm run verify
```

在 check 的基础上执行前端生产构建、离线恢复与健康检查回归，以及工作区和暂存区差异检查。测试不调用模型和真实 COS；当前回归集合以 tools/check_regressions.py 为准，功能扩展时增加对应专项测试，不能把有限集合当成全部业务验收。

统一打未提交改动包：

```sh
npm run package:changes
```

或指定输出位置，必须在项目目录外：

```sh
npm run package:changes -- --output ../benchmark-changes.zip
```

如只交付指定改动，可追加 `--files` 和项目相对路径列表；可包含已经提交的文件；未被 Git 管理且不属于未提交改动的文件会被拒绝，完整校验仍不可跳过。

校验失败会停止，不生成新包。成功后包含暂存、未暂存修改和未跟踪且未被忽略的新增文件。删除项记录在 DELETE_FILES.txt；覆盖文件后按清单删除。程序核对 ZIP 完整性和逐文件 SHA256。旧交付包不会因新一次检查失败被删除，请按新命令输出确认交付文件。

## CI 和没有 Git 目录的镜像构建

backend/Dockerfile 在 Node 阶段强制检查前端和项目脚本并构建，Python 阶段强制检查源代码复杂度和离线回归。任何一步失败都无法生成新镜像。仍需在行内验收实际镜像、平台探针和页面交互。

Python 旧代码存在超限函数。tools/quality/python-complexity-baseline.json 只记录本次治理前已提交版本的函数 AST 指纹；已有函数一旦改动就失去豁免，新增函数一律检查。即使没有 .git 目录也不会跳过新函数。扩大基线必须单独评审，不用它掩盖新问题。

检查需要本机 Python 虚拟环境和 frontend 的完整开发依赖。缺依赖时先修复安装环境，不把语法检查当成构建成功。这个流程不自动安装依赖，不修改依赖版本或锁文件。

Python 使用 3.12–3.14，生产镜像固定 3.12。AST 指纹统一保留空字段，避免 Python 3.14 的默认输出变化误伤冻结基线；不能为适配解释器而重写历史豁免清单。

前端锁文件检查同时校验根依赖与每个包的版本、下载地址和完整性记录，包括其他平台的可选依赖。行内锁文件缺失元数据时应按原固定版本补全；本地公网包与行内镜像包校验和不同时，分别验证并记录环境，不能用公网构建替代行内镜像验收。

## 浏览器与故障回归

首次运行 `npm run e2e:setup` 安装固定版本的 Playwright 和 Chromium，再执行 `npm run e2e`、`npm run e2e:explore`。已有 Edge 或 Chrome 时可设置 `E2E_BROWSER_CHANNEL=msedge` 或 `chrome` 使用本机浏览器。浏览器回归与 Docker 构建分开执行。

回归服务器使用生产共享 Flask 路由和 Worker 循环；模型命令与外部 LCR 二进制指纹使用离线模拟，并隔离数据、模型配置与存储。覆盖事务故障、文件锁、上传中断、503/非 JSON 响应、进程强制退出与明确确认后的恢复。报告须附实际持续时间与模拟范围；有限时间的通过结果不代表真实模型、LCR 二进制、COS 或生产负载已验证。

`verify` 的离线回归会清除继承的部署、模型及 COS 环境变量，测试按各自夹具设置环境，避免 Docker 默认配置污染本地临时目录。测试集合见 `tools/check_regressions.py`。
