# AACR 原始裁判的评分重试与续评

适用于选择 `original` 裁判的 AACR 批次。检视和评分是两个独立阶段，这里的重试只重发裁判请求，不启动 LCR。

## 使用方法

评分因 504、接口故障、网络中断或进程停止而未完成后，等该任务结束，再在原批次的「分步执行、恢复与导出」点击「评分」。

- 已完成的轮次在本地校验后复用，原评分文件不改写。
- 未完成轮次从头重放本地判断流程，但成功的裁判请求直接读取已保存回答，不重新调用模型。失败或尚未执行的请求才访问接口。
- 旧版本留下的 `judge-requests.json` 成功记录也可以复用，按原始请求顺序及提示词哈希逐一校验。不能匹配时停止，不猜测对应关系。
- 第一次评分纳入的案例范围固定。例如首次只评分 37/50，恢复时仍然评这 37 例。后续新增答卷不会偷偷改变已有评分范围。
- 三轮都完成且审计状态为完成后，仍然禁止覆盖正式评分。报告生成失败时可以使用「生成报告」，无需重新评分。

升级后保留原 `runtime/runs/<批次>` 下的文件即可继续。不要删除 `metrics`、`judge-requests.json`，也不要修改 `run-config.json` 或已有评分范围来绕过校验。不需要重新上传仓库或重新扫描已完成的案例。

## 超时与自动重试

单次请求保留 180 秒的客户端超时；网络错误、408、409、429、500、502、503、504，以及空回答或截断回答，最多额外重试两次。两次等待分别是 10 秒和 30 秒。401、403 等配置或权限错误直接停止。SDK 自带的额外重试关闭，避免次数叠加。

工作台不再为这一流程固定设置 900 秒上限。整步预算按案例的参考意见数、检视意见数、评分轮数和请求重试预算计算，至少一小时，并为生成报告预留时间。这是外层终止上限，提前完成即返回；平台网关的独立超时不会因此改变。

## 数据与统计

`evaluation-config.json`、`evaluation-scope.json` 保留原评分配置和范围。新增 `evaluation-resume.json` 固定数据及答卷哈希，`judge-checkpoints.json` 将轮次、请求位置和请求哈希关联到成功请求记录。答卷、数据、模型或裁判参数变化时拒绝复用。

实际访问接口的尝试写入 `judge-requests.json`，包含轮次、请求位置、尝试号、状态和已返回的用量。本地重放不新增请求或 Token 用量。接口失败而没有返回 usage 的尝试不能推算成零消耗；只能汇总已知用量。

匹配提示词、温度、行号规则、三轮独立判断及平均公式继续使用原始 AACR 实现。旧批次兼容只放行固定哈希的请求重试和恢复实现，不放行任意评分代码变化。

## 本地专项验证

```bash
PYTHONPATH=backend/src .venv/bin/python -m unittest discover -s backend/tests -p test_aacr_scoring_resume.py -v
```

验证使用临时批次和模拟接口，禁止真实网络连接。覆盖 504 重试、401 不重试、第三轮失败后恢复、旧请求记录迁移、已完成轮次保持原样、检查点索引丢失恢复、答卷漂移拒绝复用、评分范围固定和外层时限。真实行内网关与 COS 恢复仍需部署后验收。
