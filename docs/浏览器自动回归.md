# 浏览器自动回归

首次准备（项目 Python 和前端依赖按原有 `npm run setup` 准备）：

```sh
npm run e2e:setup
npm run e2e
```

`e2e:setup` 在 `scripts/e2e` 安装独立的 Playwright 依赖和 Chromium，不改变前端依赖。行内 npm 源沿用本机 npm 配置；浏览器下载需能访问 Playwright 下载源，无法访问时可改用已安装的 Chrome：只执行 `npm install --prefix scripts/e2e`，然后设置 `E2E_BROWSER_CHANNEL=chrome`。

Windows PowerShell：

```powershell
npm install --prefix scripts/e2e
$env:E2E_BROWSER_CHANNEL = 'chrome'
npm run e2e
```

macOS/Linux：

```sh
E2E_BROWSER_CHANNEL=chrome npm run e2e
```

看着浏览器执行：`npm run e2e -- --headed`。

## 覆盖与边界

- 默认主题、暗色切换、刷新回到默认主题，以及各主页面加载。
- 模型新增、修改、删除、刷新后配置保留。
- 真实仓库 ZIP（多一层目录、含无引用提交）导入；批量上传中刷新后重新选择原文件继续。
- 真实案例 ZIP 导入、改名；缺少提交时报错；错误不串到其他页面；删除被引用仓库时弹窗显示错误。
- 从页面创建测评，经过真实冻结配置、Git 校验、按需 worktree、保存答卷，再进入模拟裁判和报告。
- 串行队列、排队取消，以及测评运行中导入仓库。
- 部分案例失败后继续评分；模拟 504 触发案例自动重试。
- Worker 协作停止后标记中断，通过页面明确确认继续未完成案例，检查已完成答卷保持不变。
- 删除案例与仓库后保留历史批次。

LCR 与裁判在独立回归进程中被确定性模拟。模拟评分只检查流程，不验证评分算法或模型能力；504 验证的是整案例重试，不是 LCR 内部请求重试。基础回归的 Worker 中断验证的是协作停止；探索模式另外验证隔离服务进程强制终止与重启。二者都不能替代生产 OOM、COS 备份、认证代理和几十小时运行验收。

每次使用独立的前端构建 `output/playwright/<时间>/frontend-dist` 和数据目录 `output/playwright/<时间>/runtime`，只监听随机本机端口；清除继承的模型和 BENCH 环境配置，使用虚拟密钥、本地存储，浏览器禁止访问外部域名，模型阶段禁止联网。已有项目运行数据不作为输入，也不会删除。

## 结果

通过返回退出码 0；任一场景失败返回非零，并停止后续依赖场景。产物保存在 `output/playwright/<时间>/`：

- `results.json`：逐场景结果与耗时。
- `<场景>.png` / `<场景>-failed.png`：页面截图。
- `trace.zip`：浏览器操作和网络记录回放。
- `<场景>-page.txt`：失败页面文字。
- `backend.log`：本地服务与模拟任务执行日志。
- `runtime/`：本次隔离队列、仓库、答卷和任务记录，便于排查。

查看回放：`npm exec --prefix scripts/e2e -- playwright show-trace output/playwright/<时间>/trace.zip`。

运行通过后可以手动清理旧产物目录。回归按需在本地运行，不加入 Dockerfile，也不自动提交、发布。


## 探索性与故障验收

```sh
npm run e2e:explore
```

新增用户旅程包括：先保存配置、刷新后单例检视、只评分完整答卷、下载日志及报告；提交创建/检查后关闭或返回；服务端接受创建但响应丢失；请求未送达后先核对记录再明确重试。模拟评分范围会与实际答卷文件一起核对。

连续运行专项还包括：主动停止后排队续跑、排队期间修改模型配置、运行中拒绝删除依赖并允许导入新仓库版本、已有评分限制提前提示、内网模型地址校验，以及两轮各 50 例调度与取消第三轮排队。`scaled-queue.json` 记录工作区数量及测试服务子进程 RSS 采样；使用微型仓库与模拟模型，不等于生产规模压测或 2 GiB 限制验收。

其他探索场景包括：保存模型时关闭重开弹窗、测试时修改字段、旧请求迟到、模型删除返回 JSON/HTML 503、损坏/过期上传记录、分块已保存但响应丢失、导入已接收但响应丢失、双击保存、多标签编辑、错误结构的 HTTP 200 状态响应，以及隔离后端强制终止后的明确确认续跑。

探索模式不会在首个业务异常处停止，会保留每项截图与失败信息，继续检查其他路径。准备环境失败仍立即停止，避免把准备失败误报成业务问题。场景共用本轮隔离资源，失败需要结合前序日志判断是否存在连锁影响。

默认压力观察持续 60 秒，期间通过真实菜单连续切页、每 25 次切页刷新一次、轮询状态、运行多个排队任务，并检查同时运行任务不超过一个、任务最终完成与答卷完整性。`soak.json` 保存轮询耗时、浏览器 DOM/堆采样和垃圾回收前后堆数据；堆采样不是容器 RSS，也不是泄漏结论。

延长到三分钟，Windows PowerShell：

```powershell
$env:E2E_SOAK_SECONDS = '180'
npm run e2e:explore
```

macOS/Linux：`E2E_SOAK_SECONDS=180 npm run e2e:explore`。

单独复现某个场景（包含必要的环境准备）：

```sh
npm run e2e:explore -- --only=lost-import-completion-response
```

该模式是有界故障检查，不会自动调用真实模型或 COS，也不会自动在生产环境注入故障。真实平台的内存限制、探针和长时间运行仍需单独观察。

## Linux 2 GiB 容器验收

使用独立测试镜像与容器，生产 Dockerfile 不运行这些检查：

```sh
npm run e2e:container:build
npm run e2e:container
```

macOS 默认 Docker context 为 `colima-ccrab`，Linux 默认为 `default`，镜像为 `bench-e2e:py311`；可通过 `E2E_DOCKER_CONTEXT` 和 `E2E_DOCKER_IMAGE` 指定已有环境。镜像首次构建需要下载 Linux Git 和后端依赖，之后可以复用；`E2E_PIP_INDEX_URL` 可指定构建所用的 Python 镜像源。容器验收使用 Unix 绝对路径挂载，Windows 请在 WSL 中执行；普通浏览器回归仍可在 Windows 执行。浏览器仍在宿主机执行，后端与任务进程全部位于限制为 2 GiB、禁用额外 swap、2 CPU 的专用容器中；源代码只读挂载，数据与前端构建使用本轮独立输出目录。

检查包含环境准备、连续运行专项、导入成功响应迟到后离页并导入另一类资源、两轮各 50 例、含 128 MiB 随机二进制文件的 Git 仓库导入与检视、真实强制终止并重启容器，以及连续切页观察。`E2E_LARGE_REPOSITORY_MIB` 可调整大文件大小（默认 128，上限 256）。这是 Linux arm64/Python 3.11 的隔离业务验收，使用模拟 LCR 与裁判、本地存储；没有验证实际 LCR 二进制、COS、Gunicorn/平台代理或生产长时间运行。

`container-resources.jsonl` 保存内核 `memory.current`、`memory.peak`、`memory.stat`、`memory.events`、进程数和数据盘可用空间；`container-report.json` 保存实际镜像 ID、Docker 内存与 swap 设置、退出状态、OOM 标记和主动重启次数。验收结束会清理该轮容器及专用网络，保留输出目录和可复用镜像。

## 使用本地真实 AACR 仓库

准备已经由 `select_aacr_local.py` 选出的原 50 例，源仓库只读使用。以下命令在 macOS/Linux 执行；输出目录必须是项目的 `output/playwright` 子目录，且不能已经存在。

```sh
.venv/bin/python scripts/e2e/prepare_real_repositories.py \
  --repos-root '<AACR 仓库根目录>' \
  --selection '<原 check-result.json>' \
  --output output/playwright/real-aacr-assets
E2E_REAL_SUITE="$PWD/output/playwright/real-aacr-assets/real-suite.json" npm run e2e:container
```

准备过程验证选择报告的数据集 SHA256、50 个案例的 base/head 提交与源码对象，记录源仓库引用摘要，将完整 `.git` 历史装入普通 ZIP。它不截断历史、不创建源引用、不拉取网络，也不复制原工作目录文件；后端仍通过生产 ZIP 导入和 bundle 导出逻辑处理资源，实际检视工作区从真实案例提交完整检出。

该专项通过页面批量上传全部仓库、导入原案例配置，运行两轮各 50 例并取消第三轮排队；核对工作区数量、每例实际 HEAD、模拟调用次数、答卷文件与评分范围。另用原清单中的两个 Cherry Studio 案例验证主动停止及强制终止容器后的明确续跑。原选择报告需包含这两个案例，不适用于任意重新抽样的 50 例。

本专项保持 2 GiB、2 CPU、禁止额外 swap；不生成随机大文件。真实仓库处理的隔离阶段命令预算为 900 秒，导入及队列观察各有 30 分钟窗口，不能据此推断真实模型运行速度。`real-imports.json`、`real-queue.json` 和每例 `raw/*.workspace-evidence.json` 保存实际证据；LCR 与评分仍为模拟，不验证模型质量、真实 LCR 内部请求或 COS。普通 `e2e` 和默认容器验收不需要这些本地仓库。

只复测 Cherry Studio 恢复路径可使用 `E2E_REAL_RECOVERY_ONLY=1`，并在命令末尾加 `-- --only=real-container-restart`；这会只导入该仓库与两例恢复配置，不重复上传另外 18 个仓库。可在专项资源清单中将 `archive` 指向已校验完整 bundle 的标准仓库资源 ZIP，以复用历史；这时不能把专项算作再次验收普通仓库 ZIP 导出。

容器启动后还会运行 `check_interrupted_workspaces.py`，用临时真实 Git 仓库检查锁定工作区、目录缺失、`.git` 文件已删但目录未删完、重复清理、完整答卷保留和无关工作区保护。证据写入 `cleanup-probe.json`。该检查属于本地容器验收，不在生产 Dockerfile 中运行。
